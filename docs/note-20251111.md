# Report about changes implemented

Nov. 11, 2025

- Issue with timestamps was produced for a change in the datetime labels
  comming in the Blommberg Messages. Before, they were sufixed with
  "DT". Now they are sufixed with "DATE_TIME". The code was updated to 
  recognize correctly the new labels.
- More safeguards have been added to the time processing functions to
  detect and handle invalid or unexpected issues (see the function
  `toMicrosecondsSinceEpoch` in parser.cpp).
- To improve the output and readability of times in examples and tests for the
  C++ library, a human-readable translating functions has been added.
- The `DateTimeType` type in C++ and Go has been modified. The `offset`
  field type has been changed from `uint16_t` to `int16_t` to accomodate
  negative timezone offsets. All the related code has been updated
  accordingly.
- A prior value field has been added to the MacroHeaadlineEvent type.
  In the messages comming from Bloomberg, this field is optional based
  on the existence of a prior event. When it is not present in the
  Bloomberg message, the field is set to a default ValueType.
- In the Go library, doing this changes give the opportunity to complete
  the JSON serialization features. They were not included in the
  original requirements, but they are a convenient feature for
  development and maybe can be useful for production.
- Given the change in the label format for datetime in Bloomberg
  messages, changes in types/structures and new features added, many
  tests were broken or unsufficient. In order to assure the correctness
  of the code, a new set of binary testing data files has been collected
  (see ./data) and the tests has been updated and extended for C++ and
  Go.
- The README file has been updated accordingly to reflect the changes
  implemented. In particular, a new section about JSON serialization in
  Go has been added, and the section refered to tests has been updated.
